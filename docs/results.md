# Results and grading

Phase 5: entering, reviewing, finalizing, publishing and correcting term results. The data model
is in [`database.md`](database.md#results); this page covers the rules and the screens.

## School decisions (agreed for Phase 5)

| Question                       | Decision                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Positions                      | Rank within a class and term by total score; ties share a position and the next is skipped (1, 1, 3).        |
| Who is ranked                  | Only finalized sheets with every subject complete. Others show "Not ranked".                                 |
| Publishing an incomplete class | Allowed with an explicit acknowledgement. Students see only finalized sheets; blanks show "Not entered".     |
| Corrections after publication  | Reopen the sheet in place with a reason; it is hidden from the student until finalized again. Fully audited. |
| Extras on the sheet            | Average, grade remarks, pass/fail.                                                                           |
| Pass mark                      | 50, per subject (subject total) and overall (average, only when complete).                                   |
| Remarks                        | A Excellent / ممتاز · B Very good / جيد جدًا · C Good / جيد · D Fair / مقبول · E Weak / ضعيف · F Fail / راسب |

Nothing else is shown on a sheet: no attendance, teacher comments, signatures or class statistics,
because the school records none of them yet.

## Calculations

All in `src/domain/results.ts`, pure and deterministic; the server computes, the browser only
previews while typing.

- A subject is complete when both CA and exam are entered. Blank is "not entered", never 0.
- Subject total = CA + exam (generated by the database). Grade and remark from the session's bands.
- Subject verdict: pass when the total reaches the policy's pass mark. No pass mark, no verdict.
- Total score and average only when every subject of the level's curriculum is complete.
  Average = mean of subject totals to one decimal, halves rounded up.
- Overall verdict from the average.
- Positions as above (competition ranking over finalized, complete sheets).

## Lifecycle

```
(no sheet) → draft → finalized → [published class: visible to the student]
                        ↑   │
                        └───┘ reopen for correction (reason required)
```

- **Draft**: scores can be entered and changed. Saving creates the sheet if needed.
- **Finalized**: locked by trigger. "Finalize" finalizes every draft sheet that has every score;
  sheets with blanks only when "also finalize incomplete sheets" is ticked. Empty sheets never.
- **Reopen**: one student at a time, with a reason. In a published class this also needs
  `results.publish`.
- **Publication**: a school-wide switch per term plus one switch per class. A student sees a
  sheet only when it is finalized and both switches are on. Unpublishing needs a reason.

## Concurrency

Each score carries a version (its `updated_at` at full precision). A save sends the versions it
was based on; if any changed meanwhile, nothing is saved and the screen names the students
changed by someone else. Saves are all-or-nothing, inside one transaction that locks the sheets.

## Screens

| Route                                           | Purpose                                                                    | Permission                                                    |
| ----------------------------------------------- | -------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `/admin/results`                                | Pick a term; class readiness; school-wide publication                      | `results.read` (publish: `results.publish`)                   |
| `/admin/results/[termId]/[levelId]`             | Subject progress, class matrix, missing scores, finalize, publish, correct | `results.read` (actions: `results.enter` / `results.publish`) |
| `/admin/results/[termId]/[levelId]/[subjectId]` | Roster score entry (Enter/↓ down, ↑ up, Tab across)                        | `results.read` to view, `results.enter` to save               |
| `/admin/students/[id]/results/[sheetId]`        | One sheet as staff see it (drafts marked), printable                       | `students.read` + `results.read`                              |
| `/portal` and `/portal/results/[sheetId]`       | The student's own published sheets, printable                              | student session; ID always from the session                   |

Imported V1 (legacy) terms can be reviewed but not edited. Withdrawn enrollments are left out of
entry; their recorded sheets stay in the student's history, shown in the class of that enrollment.

Sheets print on A4 (`@page` in `globals.css`); navigation and buttons are hidden in print.

## Audit events

| Action                                    | Target  | Metadata                                                                             |
| ----------------------------------------- | ------- | ------------------------------------------------------------------------------------ |
| `result.scores_saved`                     | term    | session, term, level, subject, reason, each change `{student, ca, exam}` (from → to) |
| `result.sheets_finalized`                 | term    | session, term, level, finalized count, incomplete sheets included                    |
| `result.sheet_reopened`                   | student | session, term, level, sheet, reason, whether the class was published                 |
| `result.published` / `result.unpublished` | term    | scope (school or level), reason, readiness, acknowledged incomplete                  |

Every score change is also kept, before and after, with the staff member and reason, in the
append-only `result_score_revisions`.
